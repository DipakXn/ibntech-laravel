## Sitemap

The public index is `/sitemap.xml`. `/sitemap_index.xml` is a legacy alias. Child files look like `/page-sitemap.xml` and `/post-sitemap.xml`. They are generated by Laravel from `APP_URL`, not written as static files in `public/`.

Configure them in **Website Settings**:

- Turn the sitemap on or off.
- Include or omit `lastmod`, `changefreq`, and `priority`.
- Set the cache TTL.
- Add a `Sitemap:` line to robots.txt without rewriting existing Allow or Disallow rules.
- Enable each content type and set its defaults.
- Add custom URLs. Query strings are preserved in `custom-sitemap.xml`.

A record is omitted when **Include in sitemap** is off, the robots value is `noindex`, a redirect URL is set, or the canonical URL does not match. Child sitemaps split at 50,000 URLs.

Saving website settings clears the sitemap cache. You can also clear only that cache from **System Maintenance → Clear Sitemap Cache**.

## Robots

`/robots.txt` is generated from Website Settings, not from a file you edit over FTP. The response is not publicly cached as a static asset. After a robots change, save settings and request `/robots.txt` again.

## Visitor analytics

**Administration → Visitor analytics** shows unique visitors and page views for the public site.

- Visitors are distinct visitor IDs.
- Page views are tracked records.
- Use the preset ranges or a custom from/to date.
- Filter and sort the content table by type.

The dashboard shows a short visitor preview for administrators. Authors do not get this screen.

## Excluded IPs

**Administration → Excluded IPs** keeps office or monitoring addresses out of the analytics totals.

1. Create an excluded IP or range.
2. Save.
3. Later visits from that address are not counted.

Existing rows already stored are not rewritten by adding an exclusion. Add the exclusion before you rely on a date range.
